Практика 4: Память, отображение файлов, демонизация
Задание №4: Анализ памяти и процессов

Запустить программу с динамическим выделением памяти и проанализировать её состояние с помощью системных утилит.

**Вариант задания**
Запустить программу, которая выделяет память динамически. Проанализировать карту памяти процесса через pmap, /proc/[PID]/maps и другие утилиты.

**Особенность реализации**
Программа демонстрирует использование всех основных функций динамического выделения памяти: malloc(), calloc(), realloc(), free(). Программа работает в фоновом режиме, что позволяет анализировать её состояние с помощью системных утилит. Для корректного завершения используется обработка сигналов SIGTERM и SIGINT.

**Используемые функции и системные вызовы**
В программе используются:

- `malloc()` — выделение динамической памяти;
- `calloc()` — выделение и обнуление памяти;
- `realloc()` — изменение размера выделенной памяти;
- `free()` — освобождение памяти;
- `signal()` — установка обработчиков сигналов;
- `sleep()` — задержка выполнения.

**Используемые утилиты для анализа**

- `ps` — просмотр информации о процессе;
- `pmap` — просмотр карты памяти процесса;
- `top` — просмотр активности процесса;
- `/proc/[PID]/maps` — просмотр областей памяти процесса;
- `/proc/[PID]/status` — просмотр статуса процесса;
- `valgrind` — проверка работы с динамической памятью;
- `strace` — трассировка системных вызовов;
- `kill` — остановка процесса.

Краткое описание работы программы

Программа выделяет память с помощью malloc() (100 элементов).

Дополнительная память выделяется с помощью calloc() (50 элементов, обнулённых).

Размер первого массива изменяется с помощью realloc() (200 элементов).

Программа заполняет массив числами от 1 до 200 и считает сумму.

Программа выводит PID и переходит в режим ожидания.

Программа продолжает работать, чтобы её можно было проанализировать.

При получении сигнала SIGTERM или SIGINT программа освобождает память через free().

После освобождения памяти программа завершается.

Наблюдения и выводы

Сегменты памяти процесса:

Код программы (text) имеет права r-xp

Данные (data) имеют права rw-p

Куча (heap) динамически расширяется

Стек (stack) растёт вниз

Использование памяти:

VmSize больше VmRSS

Процесс использует минимум CPU в состоянии ожидания

Инструменты диагностики:

/proc/[PID]/maps даёт детальную карту памяти

pmap предоставляет читаемый вывод

valgrind эффективен для поиска утечек

strace показывает системные вызовы

Корректность работы с памятью:

Вся выделенная память освобождается

Утечек памяти не обнаружено

Обработка ошибок выделения памяти присутствует
